### 2026-10-14: learnings since 2026-10-13T17:32:05Z

- **Context:** PR #1734 fixed `ArrowStreamResult` so bounded SEA inline Arrow results use `SeaInlineArrowChunkProvider` even when CloudFetch (`EnableQueryResultDownload=1`) is enabled. The old check also required `!isCloudFetchEnabled()`, so hybrid inline results (an `attachment` plus a `nextChunkIndex` pointing at more inline chunks) were sent to the wrong provider.
  **Rule:** Pick the SEA result/chunk provider from the shape of the server response (e.g. `ResultData.attachment != null`), not from client config flags like CloudFetch. The server can return inline Arrow even when CloudFetch is enabled, so add a test for the hybrid inline + next-chunk case.
- **Context:** PR #1734 also fixed `ArrowStreamResult.next()`. It incremented `currentRowIndex` before advancing, and it ignored the boolean that `chunkProvider.next()` returns, so the cursor state was wrong once chunks ran out.
  **Rule:** In ResultSet/chunk iterators, check the return value of the advance call (`chunkProvider.next()`) first, and only update cursor state (row index) after the advance succeeds. Return false when advancing fails, rather than fetching a chunk that doesn't exist.

### 2026-10-27: learnings since 2026-10-26T17:31:04Z
- **Context:** In run #40422688812, the author's live e2e DeepCloneGetColumnsTests called `getMetaData().getColumns(null, schema, table, null)` and `getColumns(null, null, table, null)`. With a null catalog the driver scans every catalog on the warehouse, so the run hung until the 20-minute timeout. The author then had to remove those calls and run the test again.
  **Rule:** In live/e2e metadata tests, always pass an explicit catalog (and preferably schema) to getColumns/getTables/etc. A null or wildcard catalog scans the whole warehouse and can exceed the 20-minute test timeout. Cover null-catalog behavior with unit tests, not live calls.
- **Context:** PR #1747 removed the `UseQueryForMetadata` param, which used to affect client selection in `getClientTypeFromContext`. The reviewer found that a `@CsvSource` row in `testAutomaticClientSelectionGrid` still appended `;UseQueryForMetadata=0` and expected THRIFT, so it would fail in CI. The author had skipped it on the assumption that only Mockito tests were affected. Removing the `DatabricksJdbcUrlParams` enum entry also makes the key a silently ignored unknown param, so URLs that relied on it as a documented escape hatch change routing with no runtime signal.
  **Rule:** When you remove or repurpose a `DatabricksJdbcUrlParams` entry, grep tests for the raw key string, including URL suffixes in parameterized/`@CsvSource` rows, and run the full `DatabricksConnectionContextTest`. Also state the behavior change for users who still set the key in NEXT_CHANGELOG, because removed keys are silently ignored.
