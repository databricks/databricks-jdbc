# Learning journal 2026-11-20

### 2026-11-20: Testing — Background-thread assertions need a liveness check and per-run counter baselines
**Context:** PR #1827 changed MultiChunkExecutionIntegrationTests to run twice in one test. That exposed two gaps: `thread.join(10_000)` could time out without failing, so assertions on the background thread never ran, and the cumulative WireMock request counts included calls from the earlier run.
**Rule:** After `Thread.join(timeout)`, assert `!thread.isAlive()`, and when a WireMock request count spans several runs in one test, record a baseline count before each run and assert only the difference.

### 2026-11-20: JDBC contracts and configuration — Pin connection properties explicitly in tests when a default flips
**Context:** PR #1827 made `UseBoundedSeaApi` default to 1 regardless of the server flag. Tests for the disabled path had relied on the old implicit default, so each one had to set `UseBoundedSeaApi=0`. The enabled path is now tested both unset and explicit. A shared WireMock mapping accepts `row_offset` as either present or absent.
**Rule:** When changing a connection property's default, set the property explicitly in tests for the non-default path, test the default path with the property both unset and explicit, and verify the request differences between modes at the wire level.

### 2026-11-20: Reviewer — Update spec docs that describe a resolver when you change it
**Context:** In PR #1827, `isBoundedSeaApiEnabled` stopped using `resolveFeatureFlag`. The reviewer found that specs/features/apc-sea-support.md still described the old server-flag behavior and the cluster default of false.
**Rule:** When changing how a feature flag or connection property is resolved, grep specs/ for the method and property names and update every description of the old behavior in the same PR.
